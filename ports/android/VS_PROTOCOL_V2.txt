LAN protocol WV2 server contract, 2026-10-31 (no cryptographic authentication). All integer fields little-endian. Exactly one room per server process; each open obtains 16 OS-random bytes; entropy failure prevents open. Header = 'WV', 2, kind:u8, room[16]. Room all zero is allowed only for DISCOVER and initial HELLO. All v2 replies include actual room. New client sends both v1 and v2 DISCOVER; if both offers match, the v2 offer takes precedence. A v1-only OFFER is incompatible. A silent server is not proof of incompatibility.

Kinds and bodies:
1 HELLO: id:u32, join[16], ack_generation:u64, active_race:u64, status:u8, name[16], profile_len:u8, profile[0..64]. First join is room=0, ack_generation=0, active_race=0; reply echoes join in LOBBY. A member is bound to its exact UDP source (or GK peer), id and join nonce. Duplicate id, nonce or endpoint cannot rebind. On timeout membership is removed; reconnect is a new join nonce and only allowed in idle room. To prevent old initial HELLO resurrection, the server retains every admitted join nonce until the room closes; once 256 nonces have been admitted, further joins are refused for that room. No migration challenge, no guarantee from random IDs against an on-path attacker. HELLO with all-zero room for an already-bound endpoint is accepted only as a retry for the same id+nonce; echo prevents delayed welcome from another net_open being accepted. All other messages require exact room and member endpoint.
2 LOBBY: join[16], generation:u64, race:u64 (0 idle), aborted_race:u64 (last aborted race, 0 none), phase:u8 (0 idle/no abort owed for this join, 1 active, 2 idle/this join owes abort handling), n:u8, me:u8, host:u8, ramp:u8, km:u8, then n records: slot:u8 id:u32 status:u8 name[16] profile_len:u8 profile. generation begins 1 and monotonically increases on start, abort, and complete; never wraps. Each HELLO returns current LOBBY and current GO or pending ABORT as applicable. The server sends LOBBY before GO or ABORT, but UDP may reorder or lose either. During phase 1 no new members are admitted, so a valid LOBBY addressed to this exact join identifies an original race participant, including when its initial admission LOBBY was lost. Phase 2 is recipient-specific: exactly race=0, aborted_race!=0 and this bound join's server-recorded ack_generation<generation; it is asserted while an admitted survivor has not acknowledged the current abort generation; it remains meaningful even when every active LOBBY and every GO was lost. Phase 0 after an abort means this join is not owed that abort (either already acknowledged or newly admitted): the retained aborted_race alone does not imply participation. Before the first authenticated-by-session (not cryptographically authenticated) LOBBY echoing this join nonce, clients must not bind a room based on GO or ABORT alone; if those arrive first they may be discarded because LOBBY and pending control are retried. Clients must not acknowledge a phase-2 generation before handling its abort, and must apply generation ordering to delayed LOBBY/GO/ABORT.
3 START: generation:u64, request:u64 (nonzero unique per gesture within this join), ramp:u8, km:u8, song:u8. Only owner may start, idle, n>=2, all members ack current generation; server snapshots entire roster and seed once; increments generation and race counter, nonzero no wrap. Exact request retry during the race resends same GO; all other STARTs ignored while active. Stale generation never starts a later race.
4 GO: generation:u64, race:u64, seed:u32, ramp:u8, km:u8, n:u8, mypcb:u8; n records pcb:u8 id:u32 name[16] profile_len:u8 profile; song:u8. The frozen per-player snapshot is resent to unacknowledged members on every HELLO and at least every 0.5s until their HELLO includes both this generation and active_race. Never rebuild seed or roster on retry.
5 RACE: generation:u64, race:u64, pcb:u8, packet[0x278]. Relay exact bytes only after matching endpoint, roster and pcb, active generation/race, exact size. The server does not alter the RC payload, including 0x3c..0x63; duplicates are relayed. Only a valid packet refreshes membership liveness.
6 BYE: join[16], generation:u64. A valid endpoint and join nonce may leave even with a stale generation. Owner BYE closes room, sends CLOSED to remaining members. Non-owner BYE or timeout while in active race aborts exactly once; otherwise removes member. Generation must never wrap.
7 DISCOVER: empty. 8 OFFER: n:u8 name[16] owner:u32, response header contains room. The v2 server also responds to v1 DISCOVER with v1 OFFER for legacy discovery; therefore a v1 OFFER alone is insufficient until the v2 discovery wait has elapsed, and an accompanying v2 OFFER supersedes it. No v1 participation.
9 CLOSED: generation:u64 owner:u32, advisory; absence timeout is required. Owner timeout closes entire host, never promotes another member.
10 ABORT: generation:u64 aborted_race:u64. Upon active member loss, remove member, invalidate race, increment generation, set aborted_race, clear all survivor ack states; resend ABORT every 0.5s and on HELLO until each surviving member's HELLO confirms ack_generation>=abort generation after app teardown. LOBBY carries durable aborted_race and generation for loss recovery. New START is blocked until every survivor acknowledges current generation. Client must process newest abort before pending GO, reject old GO/RACE/ABORT, clear link/freshness, and acknowledge only after teardown; ignored datagrams cannot refresh race freshness.
11 REJECT: reason:u8. A version-1 HELLO receives a v1-framed REJECT with reason 1 (incompatible), but legacy clients may ignore it. The current v2 servers silently reject full/busy or identity-conflict joins, and clients must not infer a version from silence.
12 DONE: generation:u64 race:u64. Each member repeats only after its local normal race and result screen have ended, game teardown is complete, and it is ready to accept a new GO; continue until an idle LOBBY at a later generation arrives. Crossing the finish line or merely displaying the result screen is not sufficient. Until then the app must keep HELLO and remain in the roster. After DONE, retain the active generation/race in HELLO until the higher-generation idle LOBBY arrives, and ignore any repeated GO for that race. All original roster members must DONE before transition to idle; no ABORT on normal completion. While the room is still active, departure of any roster member aborts the race, even if that member has already sent DONE. A departure after all DONE messages have transitioned the room to idle does not abort. Owner leaves always close room. Completion increments generation and invalidates race. New START requires all current members acknowledge this generation.

TIMEOUT 6s lobby, 20s active roster including loading, and 0.5s control resend; monotonic time. All reliable claims require eventual delivery, live polling and eventual ACK. Host restart creates a new random room; no persistent state, no across-restart delivery guarantee. Room/race counters cannot be reused within the same room; random room collision is probabilistic. UDP source binding and random nonces provide session separation, not authenticated encryption or resistance to an on-path sender. Python external server owner is first joiner and its departure ends the process.
