# Project Cinder 0.2：烟雾、VS4 与故事调校

## 更新规则

- 覆盖安装同身份、同签名的 0.2，勿先卸载；不迁移或重写原有存档格式。
- 所有联机端必须更新。生产只使用 WVS4；旧 WV1/恢复协议/裸街机包不兼容，没有旧版降级入口。
- 原版资源需重新完整转换。新 MAIN 合约为 13,994 个原版来源、1,030 个 raw 来源、1,801 个输出；旧已认证资源会提示重新转换，不据此删除原版资源或存档。
- 默认候选仍使用 vk-native-staged；GLES、Vulkan 兼容路径与原生包路径都保留。

## 恢复内容与边界

1. 轮胎烟雾依据原版 `clRollUpManager` 的发射点、强度、固定时钟、50 粒子上限、25 tick 寿命与图集 UV 重建。只为玩家主视图绘制，不创造对手或后视镜烟雾；物理完成 tick 才推进，呈现帧不推进。原有轮胎痕迹保留。原版未闭合的裁剪默认值不冒充精确复现；适配层状态选择独立记录。
2. VS 顺序为匹配动画 → 地图投票 → 时间/BGM → 每人马力 → 加载屏障 → 开赛。地图复用原版计票与平票规则，昼夜平票选白天；区域内具体入口采用一次性确定的端口策略，不声称完整复现原版互动入口抽签。
3. 退出、丢失有效控制或街机计数不推进，会阻止后续物理 tick 并终止本局、清理后返房。房主丢失可由原冻结成员多数派接管；新会话、重新加入、全员确认及加载屏障均不可省略。少数分区停在恢复房间且不能开赛，可显式退出后创建新房；永久分区、NAT 不可达与任意久远历史不保证自动恢复。端点/会话绑定不是密码学认证；正在执行的同步原生硬挂无法由网络状态机中断。
4. 故事部件使用每车每套外观自己的原版子树，不使用通用替代网格。正常车辆排气 P≥2、防滚架 H≥8、悬挂 H≥6；UCF10/Celsior（含出租车）使用原版另一列阈值。R35/SpecV 没有可用防滚架网格，不补造。直接满调校亦计算强制部件。
5. 车身高度按原版精确车型与模型映射施加到车身局部根节点；轮胎、轮圈、阴影及独立刹车灯光模型不随之平移。FD3S 与共享资源包的 BA 变体、GDBF 默认高度等不能由资源包/贴图反推车主或车型。
6. 可调马力由合法永久 P+H>20 决定，不依赖直接满调校标志。普通设置只重分配已有点数；赛前选择只影响当前比赛，不写回永久进度。P10/H11 虽显示 600 匹也可选，P10/H10 则不可选。

本地 RESULTS/all-FINISH 是已观察到的本局奖励处理边界；DONE 是赛后界面结束屏障。中途取消不发奖，已经处理的有效结果不伪装回滚或重复发奖；不宣称跨设备持久化事务。

## 资源与构建约束

- 新烟雾图集属于经过认证的 MAIN 转换，不作为原版裸资源额外塞进 APK，也不新增可导入命名空间。
- 214 套车体的纹理引用不变；AO 保留既有页面布局，新增未点亮防滚架不得让 GDBF 的原有 AO 页面变成空文件。AO 数值 profile2 使用 contraction=on；物理对象保持 contraction=off。两者不能混淆，AO 源文件顶部旧编译示例不是当前 profile2 的构建权威。
- 新转换器仍验证原版来源、闭合依赖、受控生成与输出大小；AO 主机实际哈希仅为测试证据，不冒充未执行的 Android 字节金标准。
- 发行门槛是 [十二独立参考 APK 检查器](<tools/verify_cinder_race_apk.py>)，不是从候选 APK 学习“金标准”。旧门槛和旧 profile 保持历史不可变。
- 独立服务器及参数见 [VS4 协议](<docs/CINDERVS4_PROTOCOL.md>)。服务器无审阅过的车型目录时拒绝 BEGIN；Android 客户端还须在每次原生加载前验证实际车型、颜色及装饰边界。
