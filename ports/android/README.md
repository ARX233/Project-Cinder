# Android port source snapshot

This is a development snapshot, not a ready-to-build or tested release. The MIT license covers the port source only; game material is not included or licensed by it. Obtain and use any required game inputs only with appropriate rights, locally and privately. Do not commit generated resources, archives, keys, save files or build output. The local ignore rules are a safety aid, not a substitute for reviewing staged changes.

## Project Cinder 0.1 product variant

`build_cinder.sh` packages the independently installed **Project Cinder 0.1**, package `com.projectcinder.game` / versionCode1, with a new private release signer. The Java/JNI namespace remains `com.wmmt.port`; it is not the Android installation identity. Do not uninstall or overwrite the previous application: private resources and saves are separate and are not automatically migrated across UIDs. Both graphics backends of Cinder share its new package/signer and are alternatives, not two separate Cinder installations.

The landscape launcher uses the user-approved 370Z wallpaper, top-left resource selection and top-right explicitly gated game launch. Resource selection retains original ZIP/directory conversion, prepared ZIP/owned APK import and rechecking; UI state never manufactures resource readiness. The supplied shoshinsha symbol is aspect-fit rather than stretched, with a square legacy icon and a 108dp adaptive foreground whose visible artwork stays inside the 66dp circular safe zone. Artwork is generated externally by `tools/build_cinder_artwork.py`; source images, generated PNGs, keys and build outputs are not committed.

The Cinder build takes the existing runtime/baseline/sidecar inputs plus `CINDER_ARTWORK_PACKAGE` and `CINDER_EXPECTED_LAUNCHER`. The latter is a separately reviewed SDK-compiled resource-only inventory, not an APK-self-authored allowlist. `tools/verify_cinder_apk.py` validates all six branded resource members and the original runtime independently, without weakening either predecessor verifier. Supply `VERSION_NAME=0.1`, `VERSION_CODE=1`, the dedicated keystore and the usual external APFS `BUILD_OUT`/`APK_OUT`; no installation is performed. New signing material is retained privately for future Cinder upgrades and is never part of the APK/source delivery. Android rendering, device behavior and actual original conversion execution still require device verification.

## Android 1.35 original-resource conversion

The launcher now offers an in-APK original arcade ZIP/directory conversion lane, alongside the unchanged prepared runtime ZIP / owned old full APK importer. The pinned source version is main SHA-256 `2e6591153d7e599437465f736a42e27b01a3b56c881bee58365fb21d0678b1f6`: 13,360 authenticated source files, 3,642,480,523 bytes, and exactly 1,798 required outputs. A complete private readonly source snapshot precedes decoding. Packaged CPU/native converters run in a non-exported foreground `:convert` process; complete outputs are reverified, copied into a new installation and selected atomically. The same UID is lifecycle separation, not a sandbox. Failures preserve old selections, resources and independent saves; partial job files are retained.

The APK contains converter code, a pinned Python/native runtime and source/output metadata, **not original game resource payloads**. The prepared importer retains its signed baseline and old pending-recovery rules; imported APKs remain data only, never installed or executed. Optional resources are not invented or adopted from unknown output. Original-derived physics/generated code still requires separate rights review; this is not a claim the native APK is legally cleared. Current host/SDK/D8/static packaging evidence is not Android SAF, GPU, numerical, lifecycle or power-loss certification. See [original conversion usage and safety contract](docs/ORIGINAL_CONVERSION_135.md), [prepared import contract](RESOURCE_IMPORT.md) and [local prepared-resource tool](docs/RESOURCE_IMPORT_TOOL.md).

## Android diagnostic build

`DEBUG_LOG=1` enables the separate diagnostic build. On first use, select the exact `WMMT` directory in Android's internal shared storage using the system picker; ordinary scoped-storage restrictions apply. One JSON Lines `.txt` file is created for each process session (older journaled `.log` files remain supported); the app tracks and normally keeps the most recent five of its own files. Files created by a provider but never recorded in the ownership journal, including stray `.log.txt` files from earlier builds, are not automatically removed. If authorization, writing, ownership checks or deletion fail, a visible warning is shown and the game continues; unverified files are never intentionally selected for cleanup. SAF document IDs can be path-based and cannot completely rule out concurrent replacement or symlinks. This is a diagnostic build, not a guarantee that a race or crash can be reproduced.

Normal diagnostics sample every 12 render frames and every 12 simulation steps (about 5 Hz at 60 Hz); actual sequence numbers still advance on every frame or step. Shift events and selected impact/non-finite transitions receive extra detail, with a bounded burst and cooldown; these cues do not detect every incident. Before/after events have actual monotonic sample timestamps but are separately queued and can be lost independently. Records include frame and presentation timing, anonymous touch down/up/cancel phases, effective steering/throttle/braking and shifts, race configuration, vehicle position and velocity, route/section, nearest visible traffic and rival relative positions, and effect-derived impact cues. Touch coordinates, player names, account identifiers, network addresses and packet contents are intentionally excluded, but the recorded trajectory and inputs are sensitive. Logs grow for the full session; monitor free space and inspect before sharing. Queue saturation, malformed or oversized events produce gap counters; disk errors produce a warning. A crash, process kill or power loss may lose recent buffered events; asynchronous crash markers and coverage are best effort, and wall-hit values are inferred effect cues rather than ground-truth collision causes. The existing app-private stderr and performance logs are separate and are not exported by this feature.

## Build status and prerequisites

Android SDK36/build-tools36, NDK28, JDK and Python3 are needed for the current packaging route. `build_android.sh` requires explicit `ANDROID_HOME`, `JAVA_HOME`, `SIGNING_KEYSTORE`, a reviewed neutral `APP_ICON`, `GAME_DATA_BASELINES_ZIP` (inventories only), `SIDECARS_INDEX` (41 metadata rows), and `ORIGINAL_RUNTIME_PACKAGE` from the offline pinned runtime packager. The runtime package merges deduplicated Chaquopy Java, Android Python3.13.16/NumPy1.26.2/Pillow11, 16KiB-compatible native libraries, source-only app algorithms and the APK-pinned original profile. It uses signed package extraction for filesystem-based helper checks; no user source/job path enters sys.path. The new APK verifier requires the independent exact runtime allowlist plus both old metadata references; the old resource-free APK verifier remains unchanged. The build refuses game ZIP/sidecar payload inputs. Version1.35/code39 retains the package and update signer; passwords are environment references or interactive, never distributed. No install or transfer is performed. See [resource import](RESOURCE_IMPORT.md) and [legacy transaction safety](DATA_UPGRADE.md); do not clear player data to bypass failure.

**The source snapshot is incomplete for compilation.** Generated game-derived headers, `src/phys/phys_rc.c` and data files are deliberately absent. The generic generator script requires an explicit original root but intentionally stops before writing because `tools/weartexts.py`, `tools/titledb.py` and the physics roots list are excluded: they contain or may contain original-derived data. The remaining generators alone have not been verified to recreate every missing file. Newer meter, story cut-in and racing lamp inputs require separate local preparation; no complete generation procedure has been validated. `tools/time_texture.py` can generate the time texture header from a user-supplied 64×32 PNG; the image itself is not included. The Vulkan source directory includes 31 public baseline shaders and two derived from this project's SSAO/blur sources; `src/vkgl_spv.c` is generated locally by `tools/vkglsl.py` during the build. Do not upload generated outputs.

Once these gaps are addressed locally, run `./build_android.sh` with the explicit inputs above; `VK=0` selects the GLES path. This is a description of the intended process, not a claim a clean checkout builds. An isolated build with local generated inputs has compiled and linked; device verification remains necessary.

**Historical full-data builds only:** the following `external_snapshot_build.py` entry requires game-payload inputs and is not the 1.34 resource-separated build route. Its human-reviewed script pins have not been silently relaxed. Use the 1.34 metadata-only build recipe and record a separately reviewed source/provenance manifest.

For historical builds intended to stay on an external macOS APFS image, `tools/external_snapshot_build.py --help` describes an opt-in, fail-closed entry point. Prepare and independently review a complete Android source snapshot on the image first; the tool's generated manifest detects later changes but does not establish provenance or rights. It does not combine a snapshot with the current working tree or generate missing original-derived inputs. The caller supplies the external mount, its sparsebundle, a workspace on that mount, a new manifest, version, expected signing-certificate digest, independently reviewed `--expected-game-data-sha256`, toolchain and asset paths. The expected data hash must be selected independently before the build; hashing whichever archive was selected is not sufficient review. It checks the volume and reviewed script pins, then builds in a separate image-resident copy with external output and temporary directories. It checks ZIP integrity, alignment, package, version, signing certificate and explicitly supplied asset bytes; the icon and optional implicit fallback assets are not independently compared. Signing may be interactive or use explicitly supplied environment variables; no device operation is requested. This helper has mock tests and has been used for complete APK builds. It is not a sandbox: all snapshot code, inputs and tools must be trusted, and third-party system caches or concurrent mount changes are not fully controlled. A mounted image with ownership disabled or without encryption is not a private storage boundary; do not place signing keys in a snapshot.

The following describes historical local sidecar generation, not 1.34 APK payload inputs (runtime assets are now imported separately). The finish-distance display uses a locally generated `CARD_PAGES_BIN` sidecar; the existing card-page bank must be extended with the original animation assets using `tools/finish_pack.py`. Some supplied `cons_p_last_0`–`9` source images all depict zero, and the supplied metre image has a red border. The generator substitutes the existing menu distance digits and removes only the red outer border; the typeface is an approximation, not a verified restoration. For an already-extended bank, `python3 tools/finish_pack.py --repair MENU_OR_DATA_ZIP EXISTING_BANK NEW_BANK` creates a separate corrected bank without overwriting the input. Backfire uses a matched `BACKFIRE_WPK` and `BACKFIRE_BFX` pair generated locally with `tools/backfire_effect_pack.py`. The effect is disabled when its pair is absent or invalid; the local animation interpolation is approximate. Some character models lack the original `MUFFLER1/2` nodes and are reported rather than assigned invented outlets. The original-derived data files must not be committed.

Android tire tracks use original per-wheel display matrices and effect opacity read from the physics engine, the original 30-vertex FIFO per wheel, and a locally generated `tiretrack.wpk` at the game-data ZIP root. Generate it from the verified original `data/sprite/tirepattern.tga` with `tools/stage/pack_tire_track.py`, add it to a new reviewed ZIP, and commit neither original data nor generated assets. Missing or corrupt data disables the visual effect. Sampling once per simulation tick, 4-bit texture quantization and GPU behavior are not proven identical to the arcade; the effect does not modify driving physics.

The IGB2 vertex-color correction in `tools/stage/scene.py` affects newly generated assets only; existing installed WPK files are not rewritten. Rebuild and validate the affected stage data separately, keeping existing saves and data intact. For local story-car WPKs, `tools/fix_characar_wheels.py --source-engine-order` applies the statically inferred original DXT channel conversion only after checking the source image and exact encoded bytes; it writes a separate directory and reports any unknowns. The user reports that an earlier corrected build displayed properly on their phone; the subsequent 1.20 package regressed by selecting an older data ZIP. The 1.21 resource correction has not yet been confirmed on a device.

The race HUD's minimap needs one `WNV1` file per city (`navi.bin`, `navi_oosaka.bin`, `navi_hakone.bin`, `navi_nagoya.bin`, `navi_fukuoka.bin`) in the data directory. `tools/navipack.py` builds them from the original `data/minimap/*.igb` and the original executable alone; older packages that only carried `navi.bin` show an empty map box in the other cities. A failed city load now keeps the previous map in memory but refuses to draw it for the wrong city, logs the reason, and retries on the next explicit request.

The story mode's day/night card is a port extension, not an asserted arcade behaviour: the choice is asked after the rival is picked, stored separately in `story_timezone`, and no longer follows the Time Attack setting (`timezone`). Time Attack keeps its own remembered choice.

The recompiled physics inherits one unbounded walk from the original code: `CAreaProcessorJunction::MoveToPrev` decrements a section index without a lower bound, so index 0 reads `area_array[-1]`. `tools/recomp/guard_sections.py` (run by `build_phys.sh` and both port build scripts) clamps that single function to the first known section; it is idempotent and fails loudly on unexpected input. This removes one crash class seen in a device tombstone; it is not a complete proof that every reported crash had that cause.
