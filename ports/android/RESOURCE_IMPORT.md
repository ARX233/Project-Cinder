# Android 1.34：资源包分离、复用与本地导入

Project Cinder 当前启动器接受已转换的资源 ZIP，也可通过“原版 ZIP / 目录一键转换”准备资源。APK 作为输入会被拒绝。启动器的“清除资源包”经确认后删除应用管理的资源目录、导入暂存和资源登记，保留车库存档、计时成绩和化身记录。清除完成后可重新导入资源。

在“选择资源 → 导入已转换的资源 ZIP”可选择完整资源包，或只含附加文件的资源包。完整包包含 1,801 个主资源文件和 48 个附加文件，构建时应使用包含 1,801 文件清单的 `data-baselines-prepared.zip`。附加包在原版自转和完整包导入之间共享，校验后独立登记，保留当前主资源与存档。原版自转会优先使用本次转换生成的资源文件，并补入已校验的附加包或之前安装的完整包中的对应文件。单独使用原版 ZIP 时，启动器仍会提示本次转换未生成的剧情、卡片、回火、扩展表盘或音乐。

> 下文记录 1.34 的历史导入和恢复规则。1.35 新增独立“原版一键转换”通道，见[1.35 原版转换契约](docs/ORIGINAL_CONVERSION_135.md)。

## 发行边界

本版本不在 APK 内附带外置游戏主体 ZIP、卡片/扩展音乐 ZIP、剧情/卡片 BIN 或回火 WPK/BFX。仅携带已审定的旧/新运行资源文件清单（DMF1）和 41 项侧车长度/SHA-256 元数据；启动图标为新绘制的中性几何图案。

这**不是完整版权清权**：原版派生物理代码、生成表以及可能静态链接的图像仍须单独审查，不能宣传为“APK 完全不含原作内容”或保证合法。MIT 许可不覆盖原作素材或当然授权所有派生内容；用户必须有权使用导入材料。不提供原版资源下载或自动下载。

## 支持什么

- 完整旧安装：同包名、同签名升级，不卸载、不清数据。优先读独立选择记录；没有选择记录时，校验旧 `active.manifest` 或唯一受支持完成标记目录。受支持的是清单内容，不靠目录时间或玩家自报 manifest 信任。
- 主体资源：已审定 1.29/1.30/1.31 的 `4f5d…7a3e59` 和 1.32/1.33 的 `a887…f7b6` 两种 1798 文件清单。复用旧资源不会凭空获得新资源中的贴图修正。
- 导入：系统文档选择器选择自有旧直装 APK，或已经转换成移植运行格式的 ZIP。APK 仅按 ZIP 读取资源，绝不安装、加载或执行它的 DEX/ELF/启动器。
- 运行 ZIP 为扁平主体 1798 文件，可带顶层 4 个可选侧车和 `card-resources/` 下 37 文件。重压缩改变容器 SHA 可以接受，但所有主体路径/长度/SHA 必须精确命中一份 APK 内审定清单。
- 顶层剧情、卡片、回火文件分别验证；回火必须两文件同时通过。卡片/表盘/扩展音乐组须完整 37 文件通过才启用。不可用组件在界面明确提示，不回退读取旧目录中的未验证同名诱饵。

**不支持把原版街机目录简单压缩后直接运行。** 多层目录中的 `main`、`data/car/*.igb` 会识别为需要转换；完整 IGB→WPK、地图、演出等本地转换链仍是后续工作。本版不是一键原版转换器，也不执行原版街机程序。

## 启动与修复

1. 冷启动打开资源管理界面，异步校验已有资源；未就绪时不启动 native 游戏。
2. 已就绪可点“开始游戏”。选择“导入 / 修复”前说明来源权利与空间需求，文件通过 SAF 只读打开，无全盘权限。
3. 普通导入/修复写入全新 UUID 目录，验证后同步文件/目录，最后原子切换私有选择记录。旧资源、未知文件、原存档不覆盖、不删除。
4. 如果旧版已有登记的中断更新，则要求选择原先匹配的完整 APK 或原始主体 ZIP。先验证所有导入内容，再核对容器精确 SHA 与登记事务，复用既有 journaled coordinator 恢复；**不要求回装更低 versionCode 的应用**。恢复会按原登记推进受控静态资源，不等同于普通修复的旧目录逐字节不变。错来源、坏记录或未归属事务不绕过。
5. 取消在复制/哈希/解压循环检查；文件提供方使用 CancellationSignal，另线程关闭捕获的源句柄，不阻塞 UI。提供方可能不立即响应，不能保证即时取消。旧事务恢复中取消会保留 pending，之后可用同一来源继续。
6. Activity 重建时保存等待选择/排队 URI；检查忙时收到 URI 会排队并停止当前检查，不丢弃选取结果。已开始的导入在重建/进程退出后可能需要重新选择，不承诺断点字节续传。
7. 游戏已运行时不切换进程缓存的资源路径；重建只重连。同一进程 native 线程启动失败不会冻结路径或移除资源面板，可重试。

## 存储和限制

- 存档仍为应用 external-files 下 `wmmt/`。旧资源为 `re3dxplus-data/`；新导入为 `re3dxplus-imported/<UUID>/`。私有选择记录在 no-backup 的 `resource-import-v1/`；旧事务仍在 `game-data-state/`。
- 本版保留自己创建的导入暂存压缩包、未发布目录及旧目录以便诊断，不自动垃圾清理。可能同时占用所选源、暂存、解压数据和旧资源空间；检查可用空间并留安全余量，不能只看 APK 大小。
- 普通 ZIP/APK、store/deflate 与合法 APK 签名块对齐可用；不支持 ZIP64、多卷、加密、链接/特殊条目、越界/重复/别名路径。最大所选源不超过 2 GiB（具体受配置上限）；不能把任意新版本/改包作为审定资源接受。
- 全主资源哈希会消耗时间；UI 工作线程汇报进度。旧 coordinator 对完整初始化 pending 恢复逐项同步，可能明显慢于普通新目录导入；不要强制关机。
- Java ZIP reader 校验 local/central/descriptor/CRC/长度和所有主文件 SHA；Java ZipFile 不暴露 exact inflater unused-compressed-tail，不能宣传为与 Python direct-inflate canonical 校验完全同级。
- 进程级锁保护遵守协议的本应用写入；Root/ADB/第三方不合作写者不受该锁约束。目录 force 的真机文件系统支持和真实断电语义没有由主机测试证明。

## 构建与验证

`build_android.sh` 从 1.34 起拒绝所有 GAME_DATA_ZIP / CARD_RESOURCES / STORY_CUTIN_BIN / CARD_PAGES_BIN / BACKFIRE_WPK / BACKFIRE_BFX 游戏载荷输入，不再自动从 data/ 打包侧车。必须提供审定 GAME_DATA_BASELINES_ZIP、SIDECARS_INDEX、中性 APP_ICON、原签名和 SDK/NDK。Java canonical 检查与最终 APK exact-member gate 均执行；gate 同时对照两个独立元数据源。

历史 external_snapshot_build.py 的 fulldata 入口不是 1.34 构建入口，不自动放宽其人工审查的脚本 pin。发行使用完整记录当前源码 SHA、生成输入 provenance、工具/输入 SHA、签名证书与输出 SHA 的新隔离快照。所有本机生成、测试、构建产物放在 /Volumes/CodexWork，不写入原版资源目录。

主机测试覆盖纯 Java 核心与真实旧 APK/运行 ZIP 的 1798+41 文件导入、缺失轮毂修复、存档/未知树保护，SAF/Activity 实际方法提取、可选资源 native 路径和线程启动失败，以及 exact metadata-only APK gate。它们不是 Android 真机 GPU、文档提供方或断电测试；候选包发布时须明确实际验证范围。
